# 편집기

Genspark AI Slides 작업 화면의 조작 방식(모드 3분할 · 그 자리 메모 · 붙박이 서식 줄 · 위치 조정 메뉴 · 확대 바닥줄)을 차용했다.
**슬라이드 디자인은 바뀌지 않는다** — 화면은 render.js, PPTX 는 export_pptx.py 가 기존 규칙 그대로 그린다.

## 화면 구성

| 영역 | 구성 |
|---|---|
| 머리줄 | 로고·작업 공간 제목 · **덱 탭** · 저장 상태 · 세션 칩(연결됨/처리 중/연결 없음) · **▶ 발표** · **기록** · ⬇ 받기 · **내보내기 ▾**(PPTX · PowerPoint 렌더 미리보기 · 다시 렌더) · **⋯ 더보기**(글꼴 세트 · 템플릿 · 단축키 · 배치 초기화) · ▤ 오른쪽 패널 |
| 왼쪽 레일 | 썸네일(끌어서 순서 · 마우스를 올리면 복제/삭제 · 오른쪽 클릭 메뉴) · 배지 ✎ 초안 메모 · 요청(대기) · 처리(세션 처리 중) · ⚠ 검사 · ＋ 새 슬라이드 · 오른쪽 가장자리를 끌어 폭 조절(두 번 클릭 = 처음 폭) |
| 모드 바 | **✎ 편집(E) · ◎ 선택(M) · ✐ 그리기(D)** · ↶ ↷ · (편집) ＋ 추가 ▾ · (그리기) ▭ 박스 · 〰 펜 · 📍 핀 · ⚠ 검사 n · ✨ 레이아웃 고치기 · ✨ 다듬기 |
| 서식 줄 | 편집 모드에서 요소를 고르면 모드 바 아래에 나타난다 — 글꼴(본문/고정폭) · 크기 px(스피너·▾ 프리셋)·pt 표시 · 글자색(A) · **B** · 정렬 3 · ↕ 줄 간격·세로 정렬 · 🪣 채우기 · ▢ 테두리 · (선) 색·두께·화살 머리·선 모양 · ⧉ 복제 · 🗑 삭제 · 🔒 잠금 · **✥ 위치 조정 ▾** · 💬 요청 메모 |
| 캔버스 | 확대(Ctrl+휠·슬라이더 10~300%·맞춤) · Space+끌기/가운데 버튼 = 화면 이동 · 요청 표시(번호 배지 + 테두리/영역) · 메모 팝오버 · **보낼 요청 바** |
| 아래 | **노트 · 개요 · 검사** 탭(같은 탭을 다시 누르면 접힘) · ◀ n / N ▶ · − 슬라이더 ＋ · 100% · ⤢ 맞춤 |
| 오른쪽 패널 | **속성**(모든 속성·요소 목록·요소 JSON) · **요청**(목록·상태·답변·슬라이드 전체 메모) · **기록**(자동 백업으로 되돌리기) |

색은 모두 **템플릿 토큰 팔레트**에서 고른다(색의 의미 유지 — 임의 HEX 입력 없음).

## 세 가지 모드

| 모드 | 하는 일 |
|---|---|
| ✎ 편집 (E) | 클릭 = 선택(핸들), 끌기 = 이동(8px 격자, Shift = 자유), 핸들 = 크기(그림은 모서리에서 비율 유지, 선은 양 끝점), 두 번 클릭/Enter = 글자 직접 편집(Esc·Ctrl+Enter 종료 — 글머리는 "공백 두 칸 = 하위", 표는 `" \| "` 구분), 방향키 1px / Shift 8px, 오른쪽 클릭 메뉴 |
| ◎ 선택 (M) | 요소를 누르면 그 위에 **메모 팝오버**(요소 위쪽, 공간이 없으면 아래). 개체 종류별 빠른 칩(글자: 다듬기·더 길게·더 짧게·검증 / 표: 두 장으로 나누기… / 검사 결과가 있으면 "검사 결과 고치기"). **Enter = 추가**, Shift+Enter = 줄바꿈, Esc = 닫기 |
| ✐ 그리기 (D) | ▭ 박스(끌기) · 〰 펜(자유 곡선) · 📍 핀(한 지점)으로 영역을 표시하고 메모. 영역은 슬라이드 좌표(1280×720)로 요청에 저장된다 |

메모는 **초안(draft)** 으로 쌓이고 캔버스에 번호 배지·레일에 ✎ 배지가 붙는다. 아래 바 **"요청 N개 보내기"** 로 한꺼번에 세션에 보낸다(초안 → 대기, 즉시 전달).
요청 탭의 슬라이드 요청 칸도 메모 팝오버와 같이 **Enter = 메모 남기기(초안)**, Shift+Enter = 줄바꿈이다(한글 조합 중 Enter 는 조합 확정만).
"취소"는 이 슬라이드에 초안이 있으면 그 슬라이드만, 없으면 전체 초안을 지운다. 슬라이드를 넘겨도 초안·바는 유지된다.
아직 "메모 남기기"를 누르지 않은 입력(요청 탭의 슬라이드 요청 칸, 요소 메모 팝오버)도 덱·슬라이드·요소별로 브라우저에 보관된다 - 다른 슬라이드에 갔다 오거나 새로 고쳐도 남아 있고, 메모를 남기면 지워진다. 영역(그리기) 메모는 보관하지 않는다.

**✨ 레이아웃 고치기** = 이 슬라이드의 검사 결과를 담아 바로 요청(기존 디자인 유지 · 요소를 지워 경고를 없애지 말 것), **✨ 다듬기** = 스타일 유지하며 내용 논리·정렬 정리 요청. 둘 다 초안을 거치지 않고 바로 보낸다.

## 위치 조정 ✥ ▾

슬라이드 기준 정렬 6(왼쪽·가로 중앙·오른쪽 / 위쪽·세로 중앙·아래쪽) · 순서 4(앞으로 Ctrl+] · 뒤로 Ctrl+[ · 맨 앞 Alt+Ctrl+] · 맨 뒤 Alt+Ctrl+[) · 너비·높이·X·Y(px, 선은 x1·y1·x2·y2).

## 기록 · 발표 · 저장

- **기록**: 편집기가 저장할 때마다(최근 50개)와 build 덮어쓰기 전에 남긴 자동 백업 목록. "되돌리기"는 그 시점 덱으로 바꾸고 저장한다(지금 상태도 기록에 남고 Ctrl+Z 로 취소 가능).
- **발표**: F5 처음부터 · Shift+F5 현재부터 · →/Space/클릭 다음 · ← 이전 · **N = 노트·경과 시간** · Esc 끝(마지막 슬라이드로 편집기 이동).
- **자동 저장**: 편집 0.7초 뒤. **바뀐 것이 없으면 저장하지 않는다**(기록에 빈 저장이 쌓이지 않게). 2초마다 파일 버전 확인 → 밖에서(Claude) 바꾸면 자동 다시 불러오기(편집 중이면 충돌 선택).
- **새 덱·설정·엔진 변경**: 같은 2초 확인으로 작업 공간 전체를 본다 — 보고 있는 슬라이드와 상관없이 머리 아래 파란 안내 띠로 알린다.
  - 덱이 생기면(예: Claude 에게 덱 추가를 요청) 덱 탭을 바로 갱신하고 "새 덱 N개 — [열기]". 새로 고침은 필요 없다.
  - 보고 있던 덱 파일이 없어지면 [새로 고침].
  - 작업 공간 설정(`nexa-slide.json` - 템플릿·글꼴·로고·제목)이 바뀌면 다시 불러와 바로 적용한다(안내 없음).
  - 편집기 코드·템플릿 파일(엔진)이 바뀌면 [새로 고침](편집 중이면 저장하고 새로 고침).

## 화면 ↔ PPT 일치 규칙 (검증 결과)

- 글자: 한 줄 = 한 단락, 줄 간격 "정확히 size × lineHeight × 0.75 pt". PowerPoint 는 여분 줄 높이를 위 75%·아래 25%로 두므로
  브라우저 글자를 `tokens.pptTextShift`(보정 측정값) 만큼 내려 맞춘다 — 크기 12.5~60px, 줄 높이 1.0~1.8 에서 오차 ±2px.
- 둥근 사각형·타원의 PPT 글자 영역은 도형 안쪽으로 들어가 있어(반경 × 0.29289, 타원 14.6%) 그만큼 여백에서 뺀다.
- 한국어 줄바꿈: 두 쪽 모두 어절 단위(`word-break: keep-all` ↔ PowerPoint 기본). 긴 문장은 `\n` 으로 직접 끊는 것이 가장 안전하다.
- `python3 studio/compare.py ch00`: 샘플 덱 15장 모두 픽셀 차이 0.3~2.7%(글자 가장자리 안티앨리어싱 수준). 비교 이미지 `out/ch00/compare-NN.png`
- `python3 studio/check_parity.py ch00`: 코드 색·인라인 강조·plan 강조·표 격자의 JS/Python 결과 동일

## 알려진 한계

- 표 머리 행의 둥근 모서리(concept 의 `th` 반경)는 PPT 표가 지원하지 않아 양쪽 모두 직각으로 그린다.
- PPT 표는 글자가 칸보다 크면 행이 저절로 늘어난다(브라우저는 넘쳐 보임). `plan-table` 콜아웃은 행 높이 고정을 전제로 놓이므로 행이 늘면 어긋날 수 있다.
- `plan` 강조의 배경색은 run 강조색(`a:highlight`)이다 — PowerPoint 2019/365 에서 보이고, 이전 버전·다른 뷰어에서는 글자색 + 굵게만 보일 수 있다.
- 줄 배치 보정은 맑은 고딕·Consolas 기준 측정값이다. 글꼴을 바꾸면 `compare.py` 로 다시 재서 `pptTextShift` 를 고친다.
- 글자 자동 맞춤(넘치면 줄이기)·회전·그림자·투명도·그라데이션은 지원하지 않는다. 다중 선택·정렬 맞추기 도구 없음.
- PPT 에서 사람이 고친 내용은 덱 JSON 으로 돌아오지 않는다(단방향). 수정은 편집기나 JSON 에서 한다.
- 새 슬라이드(레이아웃)는 자리 표시 내용으로 만들어진다 — 내용은 요소를 고치거나 `content/` 에 쓰고 build 한다.
- 동시 편집: 한 덱을 브라우저 두 곳에서 열면 늦게 저장한 쪽이 충돌 알림을 받는다(자동 병합 없음).
