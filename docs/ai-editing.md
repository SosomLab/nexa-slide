# 새로 만든 작업 공간에서 AI 로 슬라이드 고치기

시작 페이지(또는 `init_workspace.py`)로 작업 공간을 만든 **직후부터**, AI 세션을 연결해 슬라이드를 고치고 마무리하는 과정이다.
Claude Code(터미널·VS Code·Claude Desktop)와 그 밖의 AI 코딩 도구(Codex CLI·Gemini CLI·Cursor 등)를 함께 다룬다.

관련 문서: 감시·처리 규약의 세부는 [claude-session.md](claude-session.md), 저장소에 붙여 쓰는 경우는 [new-project.md](new-project.md),
편집기 사용법은 [editor.md](editor.md), 내용 원본 형식은 [deck-format.md](deck-format.md).

## 0. 한눈에 보기

```
① 만들기(시작 페이지·명령)         작업 공간 + 덱 빌드 + 서버 시작. AI 는 아직 연결 안 됨
        │                         초안 요청을 켰으면 decks/<덱>.requests.json 에 대기(open) 요청 1건
② AI 세션 연결                     작업 공간 폴더에서 AI 를 열고 "요청 감시 시작" → 편집기 칩 "세션 연결됨"
        │                         그동안 쌓인 요청이 이때 한꺼번에 전달된다
③ 고치기 반복                      편집기에서 요청 남기기 → 보내기 → AI 가 처리 중 → 완료 + 답변 → 편집기 자동 갱신
        │                         (또는 AI 대화창에 바로 말해도 된다)
④ 마무리                           검사 ERROR 0 → PPTX 내보내기 → (git 이면) 커밋
```

| 무엇이 | 어디에 |
|---|---|
| AI 가 읽는 안내 | 작업 공간 `CLAUDE.md` — 명령·요청 감시·처리 규약(Claude Code 가 자동으로 읽는다) |
| 작성 브리프 | 작업 공간 `BRIEF.md` — 시작 페이지에서 적은 목적·대상·작성 방향·참고 자료 |
| 내용 원본 / 편집 대상 | `content/<덱>.json`(레이아웃 + 필드) / `decks/<덱>.json`(빌드 결과, 편집기가 고치는 것) |
| 요청 메모 | `decks/<덱>.requests.json` — 상태 `draft`(초안) → `open`(보냄) → `working`(처리 중) → `done`(완료) |
| 연결 상태 | `out/.studio/session.json`(감시 하트비트) → 편집기 머리줄 칩 |

## 1. 만든 직후의 상태

- **서버는 떠 있다.** 시작 페이지 버튼으로 만들었으면 Studio 가 열려 있고, 명령으로 만들었으면 `python3 <작업 공간>/nexa.py start` 로 띄운다.
- **AI 는 연결되어 있지 않다.** 편집기 머리줄 칩이 회색 **"세션 연결 없음"** 이다.
- **요청은 잃어버리지 않는다.** 연결 전에 남긴 요청(시작 페이지의 "Claude 세션에 초안 작성 요청 남기기" 포함)은 `requests.json` 에 대기로 남고,
  감시를 시작하는 순간 전달된다. 그래서 연결은 나중에 해도 된다.

작업 공간 경로는 시작 페이지 "최근 작업" 또는 `python3 <작업 공간>/nexa.py status` 로 확인한다. 아래에서 `<작업 공간>` 은 그 절대 경로다.

## 2. AI 세션 연결

연결 방식은 AI 도구가 **오래 도는 명령의 출력을 알림으로 받을 수 있는가**에 따라 셋 중 하나다.

| 방식 | 쓰는 곳 | 동작 |
|---|---|---|
| **A. 상시 감시** (권장) | Claude Code — 터미널·VS Code·Claude Desktop | Monitor 도구로 `watch_requests --stream` 을 띄워 둔다. 요청이 오면 알림으로 받아 바로 처리 |
| **B. 1회 대기 반복** | 셸 명령을 실행하는 AI(Codex CLI·Gemini CLI·Cursor 에이전트 등) | `watch_requests`(1회 모드)를 실행 → 요청이 생기면 목록을 출력하고 끝 → 처리 → 다시 실행 |
| **C. 수동** | 셸을 못 쓰거나 감시를 띄우기 싫을 때 | 감시 없이, 사용자가 "열린 요청 처리해 줘"라고 할 때 AI 가 `requests.json` 을 읽어 처리 |

### 2.1 Claude Code — 터미널

```powershell
cd '<작업 공간>'
claude
```

대화창에 한 줄:

```text
이 작업 공간의 nexa-slide 요청 감시를 시작해 줘.
```

Claude 가 `CLAUDE.md` 를 읽고 Monitor 로 다음을 실행한다(직접 적어 줘도 된다):

```text
python3 <작업 공간>/nexa.py watch_requests --stream --takeover --label "<세션 이름>"     (timeout 1800000)
```

### 2.2 Claude Code — VS Code / Claude Desktop

- **VS Code**: 파일 → 폴더 열기로 `<작업 공간>` 을 열고, Claude Code 대화창에 2.1 과 같은 한 줄.
  편집기 화면은 명령 팔레트 `Simple Browser: Show` → `http://127.0.0.1:<포트>/` 로 VS Code 안에서 볼 수 있다.
- **Claude Desktop**: Code(로컬 폴더) 세션을 새로 만들고 폴더로 `<작업 공간>` 을 고른 뒤 같은 한 줄.
  내장 브라우저 패널에서 편집기를 열면 Claude 가 화면을 직접 보며 확인할 수도 있다.
- **작업 공간이 아닌 폴더(예: 상위 저장소)에서 연 세션**이면 `CLAUDE.md` 를 자동으로 읽지 않는다. 경로를 넣어 요청한다:

```text
<작업 공간> 은 nexa-slide 작업 공간이야. 그 폴더의 CLAUDE.md 를 먼저 읽고,
Monitor 로 python3 "<작업 공간>/nexa.py" watch_requests --stream --takeover --label "<세션 이름>" 을 timeout 1800000 으로 걸어 줘.
요청이 오면 CLAUDE.md 의 처리 규약(working → 덱 수정 → content 반영 → done + reply)대로 처리하고,
{"event":"ttl"} 이 오면 같은 명령으로 다시 걸어.
```

### 2.3 그 밖의 AI 도구 (Codex CLI · Gemini CLI · Cursor 등)

이 도구들은 작업 공간의 `CLAUDE.md` 를 자동으로 읽지 않는다(Codex 는 `AGENTS.md`, Gemini CLI 는 `GEMINI.md` 를 읽는다 — 작업 공간에는 아직 만들지 않는다).
작업 공간 폴더에서 도구를 열고 아래 요청을 붙여 넣는다. 셸 명령을 실행할 수 있으면 **B 방식**:

```text
이 폴더는 nexa-slide 슬라이드 작업 공간이야. 먼저 CLAUDE.md 를 읽어(너에게도 같은 규칙이 적용돼).
편집기에서 오는 요청을 이렇게 처리해 줘.
1) python3 nexa.py watch_requests --label "<도구 이름>" 을 실행해. 요청이 생길 때까지 기다렸다가 JSON 으로 요청 목록을 출력하고 끝난다.
2) 요청마다: decks/<덱>.requests.json 에서 그 요청 status 를 "working" 으로 →
   decks/<덱>.json 을 고친다(요소 id 유지, 임시 파일에 쓴 뒤 교체) → 같은 변경을 content/<덱>.json 에도 →
   status 를 "done", reply 에 한두 문장. 모르면 status 는 "open" 그대로 두고 reply 에 질문.
3) 끝나면 1) 을 다시 실행해 다음 요청을 기다려. 내가 멈추라고 할 때까지 반복해.
```

- 1회 모드도 기다리는 동안 하트비트를 쓰므로 편집기 칩이 "세션 연결됨"이 된다. 처리 중(명령이 끝난 사이)에는 잠시 "연결 없음"으로 바뀔 수 있다.
- 도구가 명령 실행 시간에 제한을 두면(예: 몇 분 뒤 강제 종료) 끝날 때마다 다시 실행하게 한다. 요청은 파일에 남아 있으므로 빠지지 않는다.
- 셸을 쓸 수 없는 도구는 **C 방식**: 편집기에서 요청을 보낸 뒤 대화창에 "decks/ 의 requests.json 에서 status 가 open 인 요청을 처리해 줘"라고 말한다.

### 2.4 연결 확인

| 편집기 머리줄 칩 | 뜻 |
|---|---|
| 초록 **세션 연결됨** | 감시가 돌고 있다 — 보낸 요청은 바로 전달된다. 마우스를 올리면 세션 이름·마지막 확인 시각 |
| 파랑 **세션 처리 중 n** | AI 가 요청 n건을 처리하는 중(`working`) |
| 회색 **세션 연결 없음** | 감시가 없다 — 요청은 저장되고, 감시를 시작하면 전달된다 |

같은 작업 공간을 이미 다른 세션이 감시 중이면 새 감시는 `{"event":"refused"}` 를 내고 멈춘다(요청이 두 번 처리되지 않게).
넘겨받으려면 `--takeover`, 정말 둘 다 띄워야 하면 `--force`.

## 3. 고치기 — 반복 과정

### 3.1 첫 초안 (만들 때 초안 요청을 켰다면)

연결하자마자 대기 중이던 요청 "BRIEF.md 의 목적·대상·작성 방향·참고 자료로 이 덱의 초안을 써 주세요"가 전달된다. AI 는:

1. `BRIEF.md` 를 읽고 `python3 nexa.py layout_samples` 로 레이아웃과 필드를 확인한다.
2. `content/<덱>.json` 을 쓴다 — 시작용 내용을 골랐다면 그 구성을 살려 채운다.
3. `python3 nexa.py build_deck <덱> --force` → `python3 nexa.py check_layout <덱>` 으로 겹침·넘침·최소 글자 크기 ERROR 를 없앤다.
4. 요청을 `done` 으로 바꾸고 답변에 요약과 확인 질문(자료에 없어 비워 둔 것)을 남긴다. 편집기는 2초 안에 새 덱을 불러온다.

초안 요청을 켜지 않았다면 대화창에 직접 "BRIEF.md 로 초안 써 줘"라고 해도 같다.

### 3.2 편집기에서 요청 남기기

| 무엇을 | 어떻게 |
|---|---|
| 요소 하나 | **◎ 선택(M)** 으로 요소를 누르고 메모(Enter) — 예: "이 표를 두 장으로 나눠 줘" |
| 영역 | **✐ 그리기(D)** 로 박스·펜·핀을 그리고 메모 — 그 좌표와 겹치는 요소가 대상 |
| 슬라이드 전체 | 빈 곳을 누르거나 요청 탭에서 메모 |
| 보내기 | 아래 바 **"요청 N개 보내기"**(초안 → 대기). 연결되어 있으면 8초 조용해진 뒤 전달, **"지금 보내기"**는 바로 |

AI 는 요청마다 **처리 중 → 완료** 로 상태를 바꾸고 답변을 남긴다. 덱을 새로 만들었으면 편집기 덱 탭이 바로 늘어나고 "새 덱 — [열기]" 안내가 뜬다(새로 고침 불필요). 질문이 남으면(상태가 대기 그대로) 요청 탭에서 답을 덧붙이면 다시 전달된다.

### 3.3 대화창에서 바로 고치기

요청 메모 없이 AI 대화창에 말해도 된다 — "3장 제목을 결론형으로 바꾸고 표는 6행 이하로", "전체 장 수를 10장으로 줄여 줘".
AI 는 `content/` 를 고치고 `build_deck --force` → `check_layout` 으로 다시 만든다. 편집기는 바뀐 덱을 자동으로 불러온다.

### 3.4 사람이 직접 고친 내용과 content

편집기에서 직접 고친(✎ 편집) 슬라이드가 있으면 `build_deck --force` 가 멈추고 알린다 — content 로 다시 빌드하면 그 수정이 사라지기 때문이다.
AI 에게 **"편집기에서 고친 내용을 content 에 옮기고 다시 빌드해 줘"** 라고 하면 맞춘 뒤 빌드한다. 덮어쓰기 전 상태는 편집기 **기록**(자동 백업)에서 되돌릴 수 있다.

## 4. 마무리

1. 편집기 아래 **검사** 탭이 ERROR 0 인지 본다(AI 에게 "check_layout ERROR 를 없애 줘").
2. **내보내기**로 PPTX(`out/<덱>.pptx`). PowerPoint 가 있으면 렌더 미리보기로 PPT 결과도 확인한다.
3. 작업 공간이 git 저장소 안이면 AI 에게 커밋을 부탁한다 — `out/`·`decks/.history/` 는 `.gitignore` 로 빠진다.
4. 끝낼 때: AI 세션을 닫으면 감시가 멈춘다(칩 "연결 없음"). 서버는 `python3 <작업 공간>/nexa.py stop`.
   다음에 이어서 할 때는 `nexa.py start` → AI 세션 열기 → "요청 감시 시작해 줘".

## 5. 문제 해결

| 증상 | 확인·조치 |
|---|---|
| 칩이 계속 "연결 없음" | AI 가 감시 명령을 실제로 실행했는지(Monitor·백그라운드 작업 목록). 다른 폴더에서 연 세션이면 2.2 의 경로 포함 요청으로 |
| 연결됨인데 요청이 안 간다 | Monitor 가 만료된 뒤 남은 감시일 수 있다 — 같은 명령에 `--takeover` 를 붙여 다시 건다(`--stream` 은 1780초 뒤 스스로 끝나고 `ttl` 을 낸다) |
| `{"event":"refused"}` | 다른 세션이 이 작업 공간을 감시 중 — 그 세션을 쓰거나 `--takeover` 로 넘겨받기 |
| AI 가 `python3` 을 못 찾는다 | Windows 에서는 `python` 또는 `py -3` 으로 바꿔 달라고 한다 |
| 요청이 "처리 중"에서 멈춤 | AI 세션이 처리 도중 끊겼다 — 요청 탭에서 "완료로 표시" → "다시 열기"(대기로 돌아감) → 다시 연결된 세션에 전달된다 |
| build 가 멈춘다 | 3.4 — 편집기에서 직접 고친 슬라이드가 있다 |
