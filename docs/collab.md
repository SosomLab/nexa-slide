# 실시간 동시 편집 — 현재 상태 · 목표 · 방향 · 단계

> 여러 사람과 AI 세션이 같은 슬라이드 덱이나 시트를 동시에 고칠 때의 계획이다.
> 조사와 다른 제품 비교는 [research/realtime-collab.md](research/realtime-collab.md) 에 있고, 이 문서는 그 결론을 개발 계획으로 정리한다(2026-10-29).
> 원칙: **슬라이드와 시트는 편집 대상과 편집 기능만 다르다.** 세션·서버·요청·저장·동시 편집 같은 관리 기능은 한 뿌리(공용 코드·같은 API)에서 같은 방식으로 동작한다.

## 1. 현재 상태

지금은 **문서 한 통 + 버전 비교(409) + 사람이 고르기**다. 자동 병합이 없고, 덮어쓰는 단위가 덱(시트 문서) 전체다.

### 공통(서버)
| 무엇 | 지금 동작 | 코드 |
|---|---|---|
| 저장 | 문서 전체를 `PUT /api/deck/<id>?base=<버전>` 로 보낸다. 버전(mtime)이 다르면 409, `force=1` 이면 덮어쓴다 | `server.py` 973행, 쓰기는 전역 `WRITE_LOCK` 하나(111행) |
| 갱신 | 2초마다 `GET /api/version/<id>` → 바뀌었으면 다시 읽는다. 푸시는 웹 세션 진행(SSE)뿐이다 | `studio.js`·`sheet.js` 의 `setInterval(poll, 2000)` |
| 외부 변경 | 빌드·수동 편집·동기화 폴더가 파일을 바꾸면 `detect` 가 서명·해시로 찾아 원장에 남긴다(사후 기록) | `server.py` 252행 |
| 기록 | 원장 `decks/.history/<덱>/changes.jsonl`(누가·언제·무엇) + 백업 50개 | `ledger.py` |
| 누가 보고 있나 | 없다. 다른 사람이 같은 장·셀을 보고 있는지 알 수 없다 | — |

### 슬라이드 편집기
- 0.7초 디바운스로 덱 전체를 저장한다(`studio.js` 110행).
- 편집 중이 아니면 밖의 변경을 바로 다시 읽는다. 편집 중이면 충돌 배너가 뜨고 [밖의 것] 또는 [내 것]을 고른다.
  - [내 것]은 `force` 저장이라 상대 변경을 **통째로** 지운다.
- 다시 읽을 때 앞 상태를 내 실행 취소 스택에 넣는다(`studio.js` 140행). 그래서 **Ctrl+Z 가 남의 작업을 되돌릴 수 있다.**

### 시트 화면
- 저장·갱신·충돌 배너·실행 취소는 슬라이드와 같은 방식이다(`sheet.js` 411·439·1419행). 결함도 같다: 문서 전체 덮어쓰기, 남의 변경이 내 Ctrl+Z 에 섞임.
- 시트만의 위험
  - 행·열 삽입·삭제는 그 아래(오른쪽) 모든 셀 키(A1…)와 수식 참조를 다시 쓴다. 동시 편집에서 가장 충돌하기 쉬운 동작이다.
  - 열 때 비어 있는 계산값을 채워 자동 저장한다. 세션이 요청을 처리하는 동안에는 이 저장을 미루도록 이번에 고쳤다.

### AI 세션
- 세션은 사본(`draft_deck`)을 만들어 고친 뒤 `save_deck` 으로 저장한다. 사본을 고치는 데 수십 초~수 분이 걸린다.
- **고친 결함 — AI 저장이 사람의 저장을 덮던 것**
  - 전에는 `save_deck` 이 저장 직전의 버전을 기준으로 보냈다. 그래서 AI 가 사본을 고치는 사이 사람이 저장한 내용이 409 없이 사라졌다.
  - 이제 `draft_deck` 이 사본을 만든 때의 버전을 `out/.studio/draft-<덱>.base` 에 남기고(`draft_deck.py` 74행), `save_deck --from <사본>` 이 그 값을 보낸다(`save_deck.py` 44행).
  - 그 사이 사람이 저장했으면 409 로 멈추고, 세션은 사본을 다시 만들어 사람의 변경 위에 고친다.
- 사람이 고치는 곳과 AI 가 고치는 곳이 겹치는지 화면에 미리 보이지 않는다. 요청 카드의 "처리 중"과 범위 상자만 있다.

## 2. 개발 목표 (사용자 관점)

1. **내 작업이 사라지지 않는다.** 다른 사람이나 AI 가 같은 문서를 고쳐도, 서로 다른 곳을 고쳤으면 둘 다 남는다. 같은 곳을 고쳤으면 무엇이 어떻게 정해졌는지 알려 준다.
2. **남의 변경이 바로 보인다.** 2초 기다리거나 새로 고치지 않아도 바뀐 장·셀이 곧 반영된다.
3. **누가 어디를 보고 고치는지 보인다.** 다른 사람의 선택(요소·셀)이 색 테두리와 이름으로 보이고, AI 가 처리 중인 곳에는 "Claude 처리 중"이 뜬다.
4. **Ctrl+Z 는 내 작업만 되돌린다.**
5. **AI 의 큰 변경은 고를 수 있다.** 장 재구성처럼 큰 변경은 제안으로 받아 보고 장·요소 단위로 받아들인다.
6. 슬라이드와 시트에서 위 1~5가 **똑같이** 동작한다.

## 3. 개발 방향

### 원칙
| 원칙 | 뜻 |
|---|---|
| **서버가 권위** | 작업 공간마다 서버 하나가 순서와 결과를 정한다. 지금 구조(작업 공간 서버·원장)와 맞고 표준 라이브러리로 된다 |
| **요소·셀 단위 병합** | 슬라이드는 `장 id → 요소 id → 속성`(위치·크기는 한 묶음, 글은 속성 하나), 시트는 `탭 id → 셀 키 → 내용(v·f) / 서식` 이 충돌 단위다. 서로 다른 단위를 고치면 둘 다 산다 |
| **같은 단위면 정해진 규칙** | 사람끼리는 나중 것, **AI 대 사람이면 사람**, 삭제 대 수정이면 **수정**(데이터를 잃지 않는 쪽). 버린 값은 원장과 알림에 남긴다 |
| **presence 는 따로** | "누가 어디를 보는지"는 파일에 쓰지 않고 서버 메모리에만 둔다. 15초 소식이 없으면 지운다 |
| **SSE 로 내려보내기** | 저장·요청 상태·세션 진행·presence 를 탭당 연결 하나(SSE)로 보낸다. 2초 폴링은 끊겼을 때의 안전망으로 남긴다 |
| **AI 는 패치** | AI 는 기준 버전을 들고 바뀐 것(패치)만 낸다. 문서 통째 쓰기를 줄인다 |
| **한 뿌리** | 위 기능은 공용 모듈과 공용 API 에 한 번만 만든다. 슬라이드·시트는 "대상"(요소·영역 ↔ 탭·범위)과 그 표시만 다르게 둔다 |

### 하지 않는 것(지금)
- 글자 단위 동시 타이핑(OT·CRDT). 같은 글 상자·셀을 두 사람이 동시에 치면 한쪽이 진다(Figma 도 같다). 불만이 쌓이면 그 필드만 나중에 검토한다.
- WebSocket. 표준 라이브러리에 없고, SSE + POST 로 충분하다. 끌기 중 위치 공유처럼 초당 수십 건이 필요해지면 다시 본다.

## 4. 단계별 계획

각 단계는 앞 단계 없이도 배포할 수 있게 나눈다. 옛 편집기(새 옵션을 모르는 클라이언트)는 지금 동작을 그대로 쓴다.

### 0단계 — 관리 기능을 한 뿌리로 (진행 중)
- **범위**
  - 세션 칩·웹 세션 시작/중지·진행(SSE) → `wsession.js`(완료, 편집기·시트가 같이 씀).
  - 요청 패널(목록·필터·상태·답·후속·첨부·Enter 전송)·요청 폴링·서버 연결 상태 → 공용 모듈(`nexa-requests.js`).
  - 편집기·시트는 대상(장·요소·영역 ↔ 탭·범위)을 만들고 그리는 어댑터만 갖는다.
- **완료 조건**: 같은 요청·세션 동작이 두 화면에서 한 코드로 돈다. 편집기 동작이 바뀌지 않는다.
- **시험**: `editor_ui_test`(편집기 시나리오 전부 + `sheetreq_test`)·`smoke`.

### 1단계 — 잃어버리지 않기 (병합 저장)
- **범위**
  1. **서버 3-way 병합**: `PUT ?base=V&merge=1` 이면 버전이 달라도 409 대신 `기준본 · 지금 파일 · 보낸 본문`을 요소·셀 단위로 합친다.
     - 기준본은 `.history` 백업·원장 해시·서버 메모리에서 찾는다. 못 찾으면 지금처럼 409.
     - 비교는 `deckdiff` 의 짝 맞추기를 재사용하고, 시트는 셀 맵 비교를 더한다.
     - 응답 `{merged, conflicts:[…]}`, 원장에 `action: merge` 와 버린 값을 남긴다.
  2. **버전을 내용 해시·원장 순번으로**: 동기화 폴더가 mtime 만 바꿔 생기는 가짜 충돌을 없앤다.
  3. **AI 저장도 병합**: `save_deck` 이 `merge=1` 로 보낸다. 사람 우선, 버린 AI 변경은 그 요청의 reply 에 덧붙인다.
  4. **편집기·시트의 충돌 배너 → 알림**: "자동으로 합쳤습니다 · 충돌 n건(누가 이김)" 으로 바꾼다. [내 것으로 덮어쓰기]는 남기되 기본이 아니게 한다.
  5. **실행 취소 고치기**: 밖의 변경을 내 Ctrl+Z 스택에 넣지 않는다(내 변경만 되돌림). 밖의 변경 되돌리기는 변경 탭의 "직전으로" 로.
  6. **시트 행·열 삽입·삭제**는 병합하지 않는 단독 작업으로 둔다(동시에 다른 저장이 있으면 409 → 다시 읽고 다시 하기).
- **완료 조건**: 두 탭(또는 탭 + AI)이 서로 다른 요소·셀을 고치면 둘 다 남는다. 같은 속성 충돌은 규칙대로 정해지고 알림이 뜬다. Ctrl+Z 가 남의 변경을 건드리지 않는다.
- **시험**
  - 병합 golden: (기준, 상대, 나, 기대) 묶음 — 슬라이드(속성·추가·삭제 대 수정·순서)와 시트(값·서식·수식·병합 셀).
  - 잃어버린 갱신 재현: `draft_deck` → 편집기 저장 → `save_deck` 이 병합되고 사람 변경이 남는지(지금 손으로 확인한 409 를 자동 시험으로).
  - 무작위 시험: 서로 다른 (요소, 키) 변경은 순서와 상관없이 같은 결과.
  - `export_pptx` 슬라이드 XML 회귀, 시트 `export_xlsx` 결과 비교.

### 2단계 — 바로 보이기 (SSE 푸시 + presence)
- **범위**
  1. `GET /api/stream/<덱>` — 저장(원장 순번)·외부 변경·요청 상태·세션 진행을 탭당 SSE 하나로. 끊기면 `Last-Event-ID` 로 이어 받는다. 허브 중계도 흘린다.
  2. 편집기·시트가 SSE 를 받으면 바뀐 장·탭만 다시 그린다(내 편집 중이면 1단계 병합으로 합침). 폴링은 SSE 가 끊겼을 때만.
  3. `POST /api/presence/<덱>` `{tab, user, 장·요소 / 탭·범위, editing, color}` — 메모리에만, 15초.
  4. 화면: 다른 사람의 선택을 색 테두리 + 이름(슬라이드 요소, 시트 셀 범위), 썸네일·시트 탭에 사람 수.
  5. **AI presence**: working 요청의 대상(요소·범위)에 "Claude 처리 중"을 띄우고, 사람이 그곳을 고치기 시작하면 "AI 가 처리 중인 곳입니다" 를 알린다(잠그지 않음).
- **완료 조건**: 탭 두 개에서 한쪽 변경이 1초 안에 다른 쪽에 보이고, 서로의 선택이 보인다. 허브 중계(`/w/<id>/`)로 열어도 같다.
- **시험**: 헤드리스 탭 2개 시나리오(저장 → 상대 화면 반영 시간, presence 표시·15초 뒤 사라짐), SSE 끊김 → 폴링 안전망.

### 3단계 — 작업(op) 로그 + 서버 권위 + AI 제안
- **범위**
  1. 저장 단위를 문서 통째가 아니라 **id 경로 작업 묶음**으로 바꾼다: `set`(요소·속성 / 셀 키) · `insert` · `remove` · `move`(장 순서는 분수 인덱스) · 시트 `insertRows` 등.
  2. 서버가 순번대로 적용하고 결과를 덱 파일에 스냅숏으로 쓴다 — PPTX·xlsx·git·빌드는 그대로 돈다.
  3. 클라이언트는 `since=순번` 으로 놓친 작업을 받고, 내 작업은 먼저 화면에 반영한다. **Ctrl+Z = 내 작업의 역연산.**
  4. 파일을 직접 쓰는 경로(빌드·수동 편집)는 `detect` 가 diff 로 작업을 만든다.
  5. AI: `save_deck` 이 `diff(기준본, 사본)` 을 작업으로 보낸다(세션의 사본 Edit 방식은 그대로). 큰 변경은 **제안**(`.history/<덱>/proposals/<요청>.json`)으로 저장하고, 변경 탭에서 장·요소·범위별로 받아들인다.
  6. 시트 행·열에 안정 id 를 주어, 행·열 삽입도 다른 편집과 함께 병합되게 한다.
- **완료 조건**: 1·2단계 시험이 작업 로그 위에서 그대로 통과하고, 원장 재생으로 파일이 다시 만들어진다(해시 일치). AI 제안을 부분 수락할 수 있다.
- **시험**: 다중 클라이언트 시뮬레이터(파일 = 원장 재생), 역연산 undo, 제안 부분 수락, 회귀(PPTX XML·xlsx).

### 4단계 — CRDT (보류)
아래 중 둘 이상이 실제 요구가 될 때만 검토한다. 후보는 pycrdt(Yjs 호환), 트리 이동이 핵심이면 Loro. 모두 네이티브 확장이라 "표준 라이브러리만" 원칙과 Windows 설치를 다시 정해야 한다.
1. 긴 글 동시 타이핑에서 한쪽이 지는 것이 불만으로 쌓인다.
2. 서버 없이 오래 고치다 나중에 합쳐야 한다(오프라인).
3. 허브가 내용을 보면 안 된다(종단 간 암호화).
4. 같은 덱을 여러 서버가 들고 있다.

## 5. 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 병합 규칙이 사용자의 기대와 다름 | "내 수정이 사라졌다" | 버린 값을 원장·알림·변경 탭에 남기고 되돌리기를 준다. 규칙을 문서·화면 도움말에 둔다 |
| 기준본을 못 찾음 | 병합 불가 | 해시·순번 버전 + 메모리 링 버퍼. 못 찾으면 지금처럼 409(데이터는 잃지 않음) |
| 병합 결과가 레이아웃 규칙을 어김(겹침·넘침) | 보기 나쁜 장 | 병합 뒤 `check_layout` 경고를 SSE 로 보내고 검사 탭에 표시 |
| 시트 행·열 삽입과 다른 편집의 충돌 | 셀이 엉뚱한 곳으로 | 1·2단계는 단독 작업(409), 3단계에서 행·열 안정 id |
