# 0.16.0 변경 원장 - 개발 과정

편집기 "변경" 탭을 서버 변경 원장으로 키운 과정 기록. 사용자용 설명은 [change-ledger.md](../change-ledger.md), 설계 보고서 전문은 [research/change-ledger-design.md](../research/change-ledger-design.md).

## 1. 출발점 - 사용자 요구 5건 (2026-10-14)

교재 작업 공간(`sql-tutorial-with-oracle/ppt`, 덱 ch00)의 편집기에서 나온 질문·요구다.

1. 변경 기록이 유지되는 기간은? 어제 변경이 안 보이는데 유지할 수 있나?
2. 기록 탭과 변경 탭의 범위 차이가 있나?
3. 내가 수정한 내용도 변경에 포함해 기록해 줄 수 있나?
4. 내부/외부 변경 위치(출처)를 구분해 최근에 수정된 대상이 무엇인지 확인하는 것이 목표 - 구현 방법을 설계해 달라.
5. 별도 화면이 아니라 기존 변경 탭을 확장(재활용)하자.

0.15.3 의 답: 변경 탭은 브라우저 메모리(최근 30건, 화면을 연 동안)이고 밖에서 바뀐 것만 잡으며 편집기 자신의 저장은 어디에도 diff 로 남지 않았다. 기록 탭은 백업 파일 50개 목록이라 "무엇이 바뀌었는지" 가 없다. 그래서 ①은 "유지 기간 없음 - 구조적으로 어제 변경은 보일 수 없음", ②는 "범위가 다르고 사용자 편집은 둘 다 없음", ③④⑤는 원장으로 해결하기로 했다.

## 6. 알게 된 것 · 남은 일

- **startup 줄의 상세**: 서버가 꺼진 사이의 변경은 직전 상태 백업이 구조적으로 거의 없다(백업은 "덮어쓰기 직전" 에만 생기므로 마지막 줄의 `after` 상태는 다음 쓰기 때까지 백업되지 않는다). 그래서 `startup` 은 대개 `items: null` 이다. 개선안: 서버 종료 신호(`service.py stop`)에서 현재 덱을 `-stop.json` 으로 남기기 - 0.16.1 후보.
- **유예 1.5초의 빈틈**: build 가 덱을 쓰고 자기 줄을 더하기까지 2초 넘게 걸리면(백신 지연) external 줄이 먼저 생길 수 있다. 뒤늦게 해시가 맞는 build 줄이 오면 보정 메모(`kind: note`)를 덧붙이는 것은 0.16.1.
- **추정 오귀속**: 세션이 `working` 인 동안 사람이 파일을 복사하면 "Claude 추정" 으로 적힌다. 원장은 불변이고 화면 "추정" 표기와 툴팁 근거로 알린다. 세션이 `save_deck` 을 쓰면 추정 자체가 줄어든다.
- 0.16.1 후보: 이름표(`POST /api/changes` `kind: note`) · `?seq=N` 정확 순 diff 재계산 · `-stop.json` · 기록 탭과의 통합 여부.
