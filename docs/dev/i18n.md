# 다국어(i18n) 체계

화면 글은 **한국어 원문을 키로 하는 사전**으로 바꾼다. 화면 코드(`*.html`·`*.js`)는 한국어 그대로 두고, 언어 파일의 글만 고치면 모든 페이지에 반영된다. 이 문서는 그 구조와, 데이터(템플릿·시작용 내용·슬라이드 유형)와 **슬라이드 안 글(견본 내용)** 까지 넓히는 설계다.

## 1. 구성 요소

| 층 | 무엇 | 어디 | 고치는 방법 |
|---|---|---|---|
| 엔진 | DOM 의 텍스트 노드·`placeholder`·`title`·`aria-label`·`<option>`·`input[type=button]` 값을 사전으로 바꾸고, MutationObserver 로 뒤에 생기는 글도 바꾼다. `confirm`·`prompt`·`alert` 도. 언어는 `localStorage nexa-lang`(system/ko/en) 과 주소 `?lang=`. | `studio/i18n.js` | 손대지 않는다(규칙 변경 때만) |
| **언어 파일** | `window.NEXA_LOCALES.<lang> = { name, dict, patterns }`. `dict` = 원문 → 번역(정확 일치). `patterns` = 변수 든 문구 `[정규식, 바꿀 글]`(바꿀 글은 `$1` 문자열 또는 `(m, a) => …` 함수, 함수 안에서 `t(글)` 로 다른 글을 다시 번역). " · " 로 이어진 글은 조각마다 번역한다. | `studio/i18n/en.js` (한 언어를 여러 파일로 나눠도 됨 - 예: `en.review.js`) | **글만 고친다**. 새 언어 = 새 파일 하나 |
| 페이지 | 언어 파일 → 엔진 순서로 `<script>` 두 줄. 그래서 첫 그리기부터 번역된다(비동기 로드 없음). | `index.html`·`home.html`·`engine.html`·`account.html`·`auth.html`·`fonts.html`·`presenter.html`·`print.html`·`slide.html`·`docs/research/review/review.html` | 새 페이지를 만들면 두 줄을 넣는다 |
| 검사 | `node studio/tests/i18n_check.js` - 언어 파일 문법·중복 키·대표 문구 번역(실패 = 종료 코드 1). `python3 studio/tests/i18n_scan.py [editor|home]` - 편집기(5667)·격리 허브(5798)를 영어로 띄워 여러 화면 상태(탭·메뉴·창)에서 **아직 한글로 남은 글**을 모아 찍는다(슬라이드 안 글·덱 이름 같은 데이터는 뺌). 결과 `studio/tests/out/i18n_scan.json`. | `studio/tests/` | 새 화면을 만들면 scan 에 상태를 한 줄 더한다 |

키 규칙: 키는 화면에 보이는 텍스트 노드와 **글자 그대로** 같아야 한다(앞뒤 공백 제외). `<b>`·`<code>`·`<kbd>` 로 끊긴 글은 조각마다 키다(단축키 도움말이 그렇다). 변수가 든 글은 `patterns` 에 둔다. 긴 안내문은 통째로 한 키.

## 2. 데이터 라벨(템플릿·시작용 내용·슬라이드 유형·아이콘·도형 이름)

서버 JSON(`templates/*/template.json` 의 `label`·`description`, `starters/*/starter.json`, `studio/slide_types.json`, `render.js` 의 도형·아이콘 이름)은 **한국어 그대로**이고 화면에 찍힌 뒤 사전이 바꾼다. 그래서 데이터를 고치면 `en.js` 의 키도 같이 고쳐야 한다(scan 이 잡는다).

다음 단계(설계): 데이터 파일에 `i18n: { en: { label, description } }` 를 두고, 서버는 그대로 주고, 화면은 `I18N.pick(obj, "label")` 로 지금 언어의 값을 고른다(없으면 사전 → 원문). 템플릿·시작용 내용이 많아져 사전 키가 데이터와 어긋나는 일을 줄인다. 두 방식은 공존할 수 있다(pick 이 먼저, 사전이 뒤).

## 3. 슬라이드 안 글(견본 내용)의 현지화

미리 보기·레이아웃 견본·슬라이드 유형 예시의 슬라이드 글은 **내용 데이터**라 DOM 사전으로 바꾸지 않는다(사용자 덱의 글까지 바뀌면 안 되므로 `#host`·`.rs-slide`·`.pv-vp` 안은 엔진이 건드리지 않는다). 대신 **빌드 단계**에서 언어별로 바꾼다(0.22.9):

- `studio/i18n/content.<lang>.json`: 견본 글 원문 → 번역(`content.en.json` 약 330개). `content_i18n.tr(obj, lang)` 이 JSON 구조 안의 문자열을 바꾼다 - 통째로 없으면 줄마다, 그래도 없으면 안에 든 표현(두 글자 이상, 한글 경계)을 긴 것부터 바꾼다(레이아웃이 라벨을 이어 붙인 글). 키(경로·mermaid 등)는 손대지 않는다.
- 쓰는 곳: `python3 nexa.py layout_samples --json --lang en`, 편집기 슬라이드 추가 창 `/api/slidetypes?lang=` (유형 `fields` 와 레이아웃이 넣는 글까지 빌드된 슬라이드에 적용), 시작 페이지 미리 보기 `/api/preview?lang=` (레이아웃 견본은 번역된 견본으로 빌드, 빌드된 덱의 글도 한 번 더 번역). 화면은 `I18N.effective()` 를 `lang` 으로 보낸다.
- 시작용 내용: `starters/<이름>/content.<lang>/` 가 있으면 `init_workspace --starter … --lang en` 과 미리 보기가 그것을 쓴다. 없으면 **사전으로 번역해 복사**한다(0.22.10) - 사전은 `content.<lang>.json` 과 `content.<lang>.*.json` 을 모두 합친다(`load_map`). 시작용 24종의 글은 `content.en.starters1~3.json`(1,251개, 묶음별로 나눔). 새 시작용 내용을 넣으면 `studio/tests/content_i18n_test.py` 가 "한글 남음"으로 알려 주므로 그 글을 사전에 더한다. 작업 공간이 만들어진 뒤의 내용 언어는 사용자 몫이다.
- 사전 키 규칙(견본 내용): 원문 통째(여러 줄 포함)를 키로. 라벨처럼 이어 붙여지는 짧은 글(`대기`·`확정`)은 두 글자 이상이면 부분 치환에도 쓰이므로, 다른 뜻으로 쓰일 수 있는 짧은 글은 통째 키를 우선 넣는다. 경로·코드 값(`SKIP_KEYS`)은 번역하지 않는다.
- 시험 `studio/tests/content_i18n_test.py`.

## 4. 작업 분담(협업 세션과)

- 이 저장소의 언어 파일은 **영역별로 나눠** 충돌 없이 작업한다: `en.js`(편집기·시작 페이지·공통 - 개발 세션), `en.review.js`(템플릿·슬라이드 유형 검토 페이지 - 협업 세션), 필요하면 `en.docs.js`(튜토리얼·안내문).
- 같은 키를 두 파일에 두지 않는다(`i18n_check.js` 가 잡는다). 먼저 읽힌 파일의 패턴이 우선이다.
- 절차: scan 으로 남은 글을 뽑는다 → 해당 영역 파일에 키를 더한다 → `i18n_check.js` → scan 재실행으로 0 에 가깝게 → 커밋.
